## 操作と結果

- **読んだファイル**（9件）：
  - `interface/forms/soap/` の `save.php`、`C_FormSOAP.class.php`、`FormSOAP.class.php`、`new.php`、`view.php`、`table.sql`
  - `src/Common/Logging/` の `EventAuditLogger.php`、`SystemLogger.php`

- **選んだ理由**：同梱試験が操作するSOAPの保存の経路と、ログの仕組みのファイルだから。既定の選択（先頭の20件）はすべて外した。
- **説明**：「公開OSSの電子カルテ OpenEMR。試験環境（DockerのOpenEMRとMariaDB）で、職員が架空の患者を登録し、受診を作り、SOAP（主観・客観・評価・計画）を保存して開き直す。扱うのは架空の患者と架空の診療記録だけ。」

### 3. 試験の案（実際のAI、応答 `resp_07bec249b3f292b1016aef54cddcfc87d19b4d151f6969480d`、約26秒）

### 4. 同梱試験の選択と対応づけ（設定画面）

- **選んだ試験**：同梱の「OpenEMR：SOAPの保存でログに試験値が出ないか」。条件は変えていない。
- **16.2.5（機微なデータのログ出力の制限）**：観測の種類を、AIの案の「DBの行」から「コンテナのログ」に操作者が変えた。判定条件 `soap-log-app`（OpenEMR）・`soap-log-db`（DB）に対応づけた。
  - 確かめたのは、コンテナの標準出力・標準エラーに試験値が出ないかだけ。監査ログの表（DB）、コンテナ内のファイルのログ、「保護レベルに応じた制限」の方針との照合は確かめていない。
- **16.2.1（ログの「いつ・誰が・何を」）**：同梱の試験の判定条件で答えられないので、対応づけなかった。実行前の確認画面に「この試験では確かめない部分」として出た。

## 旧AIのコード説明・相談からの経路との違い

| | 旧来の経路（2026-11-02〜04） | 新しい /flow（本書） |
| --- | --- | --- |
| 確認項目のもと | 人が書いた確認項目（構成図・旧AIのコード説明・AI相談で検討） | 選んだコードと説明を、取り込んだ公開文書と照らした候補（出典つき）を、人が了承した試験の案 |
| AIが出すもの | コードの説明、確かめる部分の案 | 要求の候補と出典、ヒアリングの質問、試験の手順と合格の条件の案、試験にしない理由 |
| 試験の操作 | 同梱の固定SOAP試験を人が選ぶ | 同じ（同梱の固定SOAP試験を人が選ぶ。案から試験の設定は作らない） |
| 候補と判定条件の対応 | 人が観測の種類と判定条件で登録 | 同じ（了承した案の候補が確かめたい部分になり、人が判定条件を選ぶ） |

どちらの経路でも、AIや麦漆が照合の候補に合う操作を作るわけではない。今回、AIの4件の案のうち、同梱の試験で実行できたのは1件の一部（16.2.5 のコンテナのログの部分）だけだった。

## 再現の手順

```sh
cargo build --locked
MUGIURUSHI_AI_DIR=<mugiurushi-ai> MUGIURUSHI_AI_MODEL=<モデル名> MUGIURUSHI_AI_AUTH=proxy \
EEL_BROWSER_SECRETS_FILE=<試験用アカウントのファイル> EEL_BROWSER_EXECUTABLE=<Chromium 151.0.7922.34> \
node tools/try-openemr.mjs [--snapshot-from-git] [出力先]
```

root でない利用者で実行する。表示されたURLを開いて操作し、終了（Ctrl+C）すると、出力先に事例と流れの記録（`app/`）と要約（`summary.json`）が残る。本書の実行の出力先は作業環境の `/home/mugitest/openemr-flow-run3/` で、リポジトリには含めていない。
