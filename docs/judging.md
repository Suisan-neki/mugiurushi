# 審査用の動作手順（架空の診療所アプリ）

mugiurushi を手元で起動し、架空の診療所アプリ（[examples/clinic-tasks](../examples/clinic-tasks)）を対象に、次の流れを画面で確かめる手順です。

ガイドラインとの照合 → 試験の案の了承 → 試験の設定と実行 → 結果 → 修正用プロンプト

扱うのは架空のアプリと架空の説明だけです。実患者の情報や認証情報は入力しないでください。

## 必要なもの

| もの | 用途 |
| --- | --- |
| Rust（`cargo`） | mugiurushi 本体（実行・観測基盤）を作る |
| Node.js 22 以降 | 起動スクリプト |
| Python 3 と [uv](https://docs.astral.sh/uv/) | AIエージェント（mugiurushi-ai）と、架空のアプリの実行 |
| OpenAI の APIキーとモデル名 | 照合と試験の案を作る。1回の照合で入力およそ1.2万・出力およそ3千トークン |
| git | 架空のアプリのコミットを作る |

Linux と macOS を想定しています。

## 1. 取得と準備（初回だけ）

```bash
git clone https://github.com/Suisan-neki/mugiurushi.git
```

```bash
git clone https://github.com/Suisan-neki/mugiurushi-ai.git
```

```bash
cd mugiurushi && cargo build --locked && cd ..
```

照合に使う公開文書を取り込みます（公開元からPDFを取得します。数分かかります）。

```bash
cd mugiurushi-ai && uv sync && uv run mugiurushi-ai ingest --all && cd ..
```

提供事業者向けのガイドライン（経済産業省のPDF）は、自動取得が拒否される場合があります。その文書が無くても動きます。取り込む場合は、公開元から手で保存したPDFを指定します。

```bash
cd mugiurushi-ai && uv run mugiurushi-ai ingest provider-security-main --file ./01gl_20250328.pdf && cd ..
```

## 2. 起動

```bash
cd mugiurushi
```

```bash
MUGIURUSHI_AI_DIR=../mugiurushi-ai MUGIURUSHI_AI_MODEL=<モデル名> OPENAI_API_KEY=<APIキー> node tools/try-clinic.mjs
```

「準備ができました」のあとに表示されるURLをブラウザで開きます。終了は Ctrl+C です。架空のアプリの作業用ファイルは終了時に消えます。

## 3. 画面での確かめ方

1. **照合の準備**：説明の欄に、起動時に表示される例文を貼り付け、「照合を始める」を押します。送る内容が表示されるので、確認して送ります。
2. **照合とヒアリング**：ガイドラインごとに、満たしていない可能性がある項目が優先度順に出ます。ヒアリングの質問には答えなくても先へ進めます。
3. **試験の案の了承**：AIが出した試験の手順と合格の条件を読み、「了承して確認項目に登録する」を押します。了承するまで試験は実行されません。
4. **試験の設定と実行**：結果の画面の「試験を設定して実行する」から設定画面を開き、下の表のとおり入力して「試験を始める」を押します。架空のアプリが手元で実際に起動されます。
5. **結果**：実際に確かめた項目だけが「試験で不足を確認」または「期待どおり」になります。実行していない試験や、判定条件に対応づけていない項目は、そのことを示し、合否には数えません。
6. **修正用プロンプト**：直したい項目を選ぶと、ガイドラインの該当箇所・判定条件・結果・関係するコードをまとめた依頼文が出ます。手元のAIにそのまま渡せます。

### 試験の設定の例

試験の設定は、AIの案から自動では作りません。開発者が設定画面で入力します。架空のアプリでは次のように入力すると、案の内容を確かめられます。

**担当外の職員への表示と、操作の記録**

| 欄 | 入力 |
| --- | --- |
| 起動対象 | `clinic_tasks.py` |
| 引数（1行に1つ） | `--dir` / `.` / `--user` / `nurse1` / `add` / `P001` / `{{test_value}}` |
| 保存先 | `access.log` |
| 後から読み出す：起動対象 | `clinic_tasks.py` |
| 後から読み出す：引数 | `--dir` / `.` / `--user` / `nurse2` / `list` |
| 判定の条件1 | 範囲「受付」、終了コード、0（正常終了）で終わる |
| 判定の条件2 | 範囲「担当外の職員の一覧に出ない」、後からの読み出し、次の文字列を含まない、`{{test_value}}` |
| 判定の条件3 | 範囲「操作の記録が残る」、保存先の内容、次の文字列を含む、`user=nurse1 action=add` |

**保存先の外のファイル名**

| 欄 | 入力 |
| --- | --- |
| 起動対象 | `clinic_tasks.py` |
| 引数（1行に1つ） | `--dir` / `.` / `--list` / `../outside.tsv` / `--user` / `nurse1` / `add` / `P001` / `{{test_value}}` |
| 判定の条件1 | 範囲「保存先の外の指定を拒否する」、終了コード、0以外（失敗）で終わる |
| 判定の条件2 | 範囲「保存先の外へ書き込まない」、標準出力、次の文字列を含まない、`追加しました` |

「実行前に確認する」の画面で、照合の項目ごとに、どの判定の条件で確かめるかを選んでから実行してください。選ばなかった項目は「未確認」と表示されます。

## 結果の見方の注意

- AIの応答は毎回変わります。照合の項目の数や試験の案の数は、実行ごとに違います。
- 照合の結果は、ガイドラインへの適合・準拠を判断するものではありません。合否は、実際に動かして判定の条件と照らした結果だけで決まります。
- 2026年11月7日の実行記録は [validation-clinic-demo-2026-11-07.md](validation-clinic-demo-2026-11-07.md) にあります。

## 画面を操作せずに一通り確かめる場合

上の入力を決まった規則で自動で行い、記録と画面写真を `test-results/` に残すスクリプトもあります（Playwright のブラウザが必要です）。

```bash
MUGIURUSHI_AI_DIR=../mugiurushi-ai MUGIURUSHI_AI_MODEL=<モデル名> OPENAI_API_KEY=<APIキー> node tools/clinic-demo.mjs
```
