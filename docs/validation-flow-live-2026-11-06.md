# 新しい流れ（/flow）を実際のAIエージェントで通した記録（2026年11月6日）

今回の検証では、実際の mugiurushi-ai を起動して `gpt-6.1-terra` を設定し、mugiurushi の新しい画面 `/flow` で「照合の準備 → 照合とヒアリング → 試験の案 → 了承して確認項目に登録 → 結果の画面」までを1回通した。対象は公開リポジトリ `sjl/t` の `70817fd5264caa926fd8ee88b52dfc7d25f4240c`。送ったのは公開コードの抜粋と、架空の説明（「架空の診療所で、職員が患者ごとの連絡タスク（架空の氏名・電話番号・内容）を管理するのに使う」）だけ。

## 実行したもの

| 項目 | 値 |
| --- | --- |
| mugiurushi | `claude/guideline-flow`（この記録と同じコミットの作業ツリー） |
| mugiurushi-ai | `0d477356c1a74a02a225578d36d2e0f83b3aa840`（取り込み済みの文書18件。提供事業者ガイドラインは運営者が取得したファイルを `--file` で取り込んだ） |
| モデル | `gpt-6.1-terra`（APIが返したモデル名も同じ） |

再現の手順（mugiurushi-ai 側で文書を取り込んでおく）：

```sh
cargo build --locked
MUGIURUSHI_AI_DIR=<mugiurushi-ai のチェックアウト> MUGIURUSHI_AI_MODEL=gpt-6.1-terra MUGIURUSHI_AI_AUTH=proxy \
  node tools/flow-live.mjs
```

記録は `test-results/flow-live.json` と画面写真 `test-results/flow-live-*.png`（リポジトリには含めない）。

## 確認できたこと・できていないこと

- 確認できた：実際の mugiurushi-ai と実際のモデルで、選んだファイルの抜粋を送る照合、ヒアリングの質問の表示と回答、試験の案の受け取り、了承した案から確認項目と確かめる部分の登録まで。
- 合成の試験（`tools/flow-smoke.mjs`、偽のAIエージェント）で確認した：結果の画面で不足を確認した項目と期待どおりだった項目を分けること、修正用のプロンプトの中身、前のコミットとの比較、利用者からの質問への回答の表示、試験で確かめられない候補を出さないこと。観測の状態は事例の記録を差し替えて確かめており、実際の試験は実行していない。
- 確認していない：試験の案から実行の設定を自動で作ること（まだ作っていない。了承した試験は既存の画面で設定してから実行する）。今回の対象は診療所向けのシステムではなく、日本語のガイドラインから試験で確かめられる候補は出なかった（出たのは英語の ASVS の要求だけ）。候補と案の中身の良し悪し。
