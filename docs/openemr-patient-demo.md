# OpenEMRで患者Aの保存と患者Bへの影響を確認する

この文書は、保存に関する追加の確認例を扱う。デモ全体の中心となる問いと構成は[診療データの保存を確かめるデモ](openemr-storage-demo.md)を参照する。患者A・Bの比較は、その問いから検討できる試験の一つであり、常に必要な手順ではない。

この試験は架空の患者だけを使う。OpenEMRで患者BのSOAPを保存して内容を読み取り、患者AのSOAPを保存した後、Bの同じ行を読み直す。記録した条件と結果を、動画の説明に使うための手順である。

## 確認すること

- AとBの患者IDが異なる。
- Aの患者IDと受診・SOAPの患者IDが一致し、SOAPの4項目を画面とDBから読み直せる。
- Bの患者IDとSOAPの患者IDが一致する。BのSOAPのID・患者ID・4項目が操作前後で一致する。
- DBを読み取れない場合や同じ試験値の行が複数ある場合は、比較できなかったと記録する。

この試験はBの別の記録が新たに作られていないこと、患者AのSOAPと受診の関連、認可、監査履歴、暗号化、長期保存を検証しない。指定した試験条件以外での動作や、医療情報の規制全体への適合を保証しない。実行イメージと参照したGitコミットのコードが同一かは未確認である。

## 実行の準備

[開発・実行の手引き](development-guide.md)に沿ってRust、Node.js、Playwright、指定版のChromium、Dockerを用意する。試験対象に使うOpenEMRとDBは試行ごとに新規作成・削除する。既存の病院システムや実患者データには接続しない。基盤とブラウザ操作器はホスト上で動くため、信頼できる対象を専用の試験環境で実行する。

試験用アカウントの値は公開された架空の値であり、実環境に流用しない。次の操作では、現在のシェルで試験用ファイルを作り、そのパスを麦漆へ渡す。

```sh
npm ci --ignore-scripts
npx playwright install chromium
umask 077
printf '%s' '{"username":"eel-operator","password":"eel-pass-trial"}' > /tmp/mugiurushi-openemr-demo-secrets.json
EEL_BROWSER_SECRETS_FILE=/tmp/mugiurushi-openemr-demo-secrets.json cargo run
```

作業終了後は試験用の認証ファイルを削除する。AIやDifyの利用には別途運営者側の設定が必要であり、この試験の成功だけではAI接続の成功は確認できない。

## 動画で見せる流れ

1. 対象として`openemr/openemr`を読み込み、診療記録の保存に不安があるという確認項目を登録する。
2. 「ブラウザで試す内容を選ぶ」から「OpenEMR：患者Aの保存と患者Bへの影響」を選ぶ。参照する版、実行イメージ、操作と判定条件を実行前に確認する。
3. 試験を実行し、麦漆が新しい試験環境でBを作成し、その後Aに保存する。実行に時間がかかる場合は録画を編集し、省略したことを説明する。
4. 結果画面で患者とSOAPの対応、AとBのIDの違い、Bの記録の操作前後の比較を示す。各結果と元の観測を確認する。
5. 今回確認していない範囲を示し、追加の確認が必要であると説明する。

AIとの相談から試験条件へつなぐ場面は、録画に使う環境で実接続を確認できた場合に収録する。未接続の場合は、確認項目を手動で登録したと説明する。
